<objective>
Fix the "BOTTOM OVERFLOWED BY 6.5 PIXELS" error on the staff dashboard _KpiCard widgets.

Purpose: The GridView.count with childAspectRatio: 1.3 constrains card height. On certain screen widths, the fixed-size content (icon container 40px + headlineMedium text + label + 32px vertical padding from GlassCard) exceeds the allocated height by ~6.5 pixels. The fix makes the card content layout flexible so it adapts to any constrained height.

Output: Overflow-free dashboard KPI cards on all screen sizes.
</objective>

<context>
@mobile/lib/features/staff/screens/staff_dashboard_screen.dart
@mobile/lib/shared/widgets/glass_card.dart
@mobile/lib/core/theme/app_spacing.dart

Root cause analysis:
- `GridView.count` with `childAspectRatio: 1.3` gives each card a height of `cardWidth / 1.3`
- On a 2-column grid (mobile) with 20px padding + 16px crossAxisSpacing, each card is ~(screenWidth - 56) / 2 wide
- At ~360dp screen width: cardWidth ≈ 152, cardHeight ≈ 117
- Card content needs: GlassCard padding (32) + icon container (40) + Spacer + headlineMedium (~28) + SizedBox(2) + labelSmall (~14) ≈ 116-124px
- The tight fit causes overflow on screens where the math pushes content beyond the allocated height
- `Spacer()` (flex: 1) consumes remaining space but cannot shrink below 0, so fixed children overflow

Fix strategy:
- Replace `Spacer()` with `SizedBox(height: 4)` — removing unbounded flex that fights the constrained height
- Wrap the icon container in `Flexible` so it can shrink slightly if space is very tight
- Reduce icon container padding from 10 to 8 (saves 4px) for a bit more breathing room
- Keep existing `FittedBox` on value and label (already correct)
- This approach is robust: content sizes down gracefully instead of overflowing
</context>
